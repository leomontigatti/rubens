# Codebase map

Where code lives, and where a change usually goes. The map lists directories, not
every file: a file's own top comment and its tests say the rest. Update this page
when a directory is added, moved or given a new job.

## Where a change goes

- **A screen**: a route file in `src/routes/`, with its loader and action beside it
  when they are small. Shared presentational pieces go in `src/components/`.
- **A query or mutation on the organization's data**: a function in the area's module
  in `src/organization/` (`offices.ts`, `appointments.ts`, …), taking the database
  and the acting member, and a one-line method on the `Organization` class that
  states the roles it needs and calls it.
- **A server function**: in a `*.functions.ts` file, it only calls
  `withOrganization((organization, caller) => organization.<method>(caller, data))`
  (`src/server/with-organization.ts`). A refusal comes back as `{ ok: false, reason }`.
- **A schema change**: edit `src/organization/schema.ts` (or `whatsapp-schema.ts` for a WhatsApp table), run `pnpm organization:generate`,
  and review the generated SQL. Migrations on `main` are never edited.
- **A background job**: a row in the organization's object and its one alarm (ADR-0008):
  `src/organization/outbox.ts` sends the messages to patients when due
  (`template-messages.ts` queues and rebuilds those of the organization's own templates,
  each at its timing; `templates.ts` is where an admin creates, edits and deletes them), and
  `src/organization/assistant.ts` runs the patient assistant's turn once a conversation's
  wait is over (`turn-replies.ts` sends its reply, after the clinical check; `turn-retries.ts`
  retries a turn the model could not read, then hands it off; `assistant-usage.ts` records
  the tokens of each model run, for the WhatsApp settings' month totals;
  `assistant-sandbox.ts` runs the same turn for the settings' sandbox, inside
  transactions it rolls back), and the
  object's `alarm()` is set to the earliest due item. Payload
  contents are never logged.
- **A pure rule** (availability, formatting, state transitions): a module in `src/lib/`
  or beside its feature, tested without a database or React.

## Tests

- `*.test.ts(x)` beside the code: unit tests (`pnpm test:unit`).
- `*.workers.test.ts` beside the code: tests in the Workers runtime (`pnpm test:workers`),
  the organization object's methods on real SQLite, its fixtures in
  `src/organization/organization.test-support.ts`.
- `tests/e2e/*.spec.ts`: browser specs against the production build (`pnpm test:e2e`),
  one file per flow or race ([tests/e2e/README.md](../../tests/e2e/README.md)).
- Fixtures shared by one module's tests sit in `<name>.test-support.ts`; the object's
  tests share `src/organization/organization.test-support.ts`, and fixtures shared
  across other modules sit in `src/test-support/` ([coding-standards.md](./coding-standards.md#test-support-files)).
